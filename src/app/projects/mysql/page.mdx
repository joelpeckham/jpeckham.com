You can ship Laravel apps for years without knowing what MySQL actually does with your migrations. Then one list endpoint slows to a crawl, `EXPLAIN` reads like tea leaves, and everyone's advice is "add an index" with no opinion about which one or why.

This series fixes that. Each article takes one layer of MySQL and InnoDB (column types, primary keys, indexes, query shapes, and eventually the engine internals) and builds a mental model you can use in a code review the same day. Instead of squinting at static diagrams, you get small interactive demos you can poke until the idea clicks. The app examples are Eloquent, because that's what I write at my day job, but everything is really about the SQL underneath, so none of it expires when you switch ORMs.

Start at the top. Each article assumes the ones before it.
